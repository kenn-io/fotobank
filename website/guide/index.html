Photo authority guide

Follow one photograph through the system.

The original remains exact while each layer adds explicit, replaceable meaning around it.

  1. 01

    Source boundary

    Observe a settled source.

    Fotobank waits until size and modification time stop changing, then reads the exact bytes. The source is never renamed, rearranged, or edited in place.

    IMPORT SOURCE/camera/DCIM/IMG_1042.CR3read-only observation
  2. 02

    Docbank authority

    Preserve exact content.

    Fotobank supplies the expected SHA-256 and size. Docbank accepts those bytes into content-addressed storage and creates an immutable version under a stable node.

    Content and storage
    CONTENT RECEIPTnode 481 · version 7sha256: 71b8…09e4
  3. 03

    Fotobank meaning

    Relate the files as one photo.

    The product catalog records which file is primary, which is the camera source, and which sidecar belongs to it. Each relationship points to an exact Docbank version.

    Asset data model
    ASSET↳ JPEG · primary↳ RAW · camera source↳ XMP · sidecar
  4. 04

    Rebuildable outputs

    Project useful views.

    Fotobank extracts photo metadata and generates thumbnails from the recorded version. These outputs speed up browsing, but they can be discarded and rebuilt without changing the record.

    EXIFGPSTHUMBSEARCH
  5. 05

    Working files

    Check out ordinary files.

    A checkout materializes selected exact versions into a deliberate working directory. External editors, file managers, and shell tools can use normal files there.

    When a settled tracked file changes, Fotobank commits it as a new immutable Docbank version. The checkout never becomes the silent archive authority.

    WRITABLE CHECKOUT2026 / selects / field-studytracked · explicit · recoverable
  6. 06

    Photographer decisions

    Organize without rewriting the record.

    Albums, visibility, sharing, and other catalog choices stay in Fotobank. They can change without copying the original or changing what a Docbank version means.

    ALBUMHIDDENSHAREMAP
  7. 07

    Recovery

    Prove the archive still holds.

    Docbank verifies retained content. Fotobank snapshots and restores its product catalog under a coordinated database lock. Checkouts and projections can be reconstructed from those authorities.

The next boundary: shared intelligence.

Photo metadata, canonical previews, embeddings, and retrieval that describe one exact file version belong in Docbank. Ratings, picks, albums, people identities, and other photographer decisions belong in Fotobank.

This avoids building the same generic intelligence twice while keeping the photo-library experience focused.
